# IO 外接记忆库 · 设计 spec v1

> 状态：骨架已对齐，可进入实现/eval 阶段。
> 标注约定：【已定】可实现 · 【待 eval 定参】机制定了、参数不在 eval 前拍死 · 【延后】不阻塞当前设计。
> 本 spec 汇总自记忆框架设计讨论，参考了 MemPalace / memU / imprint-memory / Ombre-Brain / ex-skill 与现有 feedling-mcp。

---

## 0. 定位与第一性原则

**一句话定位**：一个加密的、用户可见的**权威外置卡库**，对 agent 是插件式外设；**agent 拥有判断，库拥有契约**；VPS 与 API 两条路**只在"谁来提议落卡"分叉**，其余全部共用。

四条原则：

1. **propose 与 integrate 分离。** propose（什么值得记，taste）按路径分叉；integrate（怎么入库，契约）路径无关、由库拥有、enclave 确定性执行、**不跑 LLM**。
2. **草稿 → 落卡 = 慎重发布。** 会话内是草稿（在上下文/私有草稿里），落卡是把草稿里值得留的发布成卡。草稿私有、永不浮现——这杜绝"感知不对称/嫉妒"那类 bug 复发。
3. **一切加密、enclave 内 per-request 解密、enclave 外永无明文。** ChaCha20 解密是 GB/s 级，可以全解；真瓶颈是 LLM 上下文预算，不是解密。
4. **永不硬删（用户主动删除除外）。** supersede/做梦只软化、保留链——历史、回滚、"记得过程"由此自动得到。

## 1. 卡 schema（v1）

判准：**每个字段必须有一个用它的操作；没有操作认领的字段砍掉。**

| 字段 | 说明 | 认领它的操作 |
|---|---|---|
| `id` | 卡 id | — |
| `verbatim` | 密文体，逐字全文，深读时 fetch | 召回深读 + "记得过程"原则 |
| `summary` | 一行 label，落卡时生成、受质量管控 | agentic 召回（索引的接口本身） |
| `is_open_thread` + `follow_up` | 是否未闭合的线 + 跟进提示 | 主动浮现 |
| `topic_tags` | 软标签 | index 预筛 |
| `bucket_refs` | 所属细桶（实体/话题）的 id 列表 | 索引归属 / 限范围 |
| `status` | active / superseded / contradicted / archived | integrate 状态机 / 召回过滤 |
| `superseded_by` · `supersedes` | 演化链指针 | integrate / 历史 |
| `valid_from` · `valid_to` | 有效期窗口（借 MemPalace 时序图思路） | 演化链 / 渐进变化 |
| `importance` · `last_active` · `last_surfaced` · `surface_count` | 衰减 + 浮现去重 | 衰减 / 浮现 |
| `salience` | 单一强度位（先不上情感分类法） | 浮现排序 |
| `pinned`(常青) · `decay_exempt` | 豁免衰减 | 衰减 |
| `provenance` | {route, committer, confidence, source_ts} | 矛盾消解 / 信任 / eval |

被砍掉的装饰字段：`card_type` 枚举（只保留 `is_open_thread`）、`about`（移到索引轴，见 §2）、`milestone_signals`（移到 capture 判断启发式，非存储字段）、富情感 taxonomy（先用单一 `salience`）。

## 2. 索引（两层，互不混淆）

### 2.1 检索层（给 agent 用）【已定】
一个**扁平、每用户涌现、会生长的命名桶集合**——实体和话题混在一起，每个桶是 `妈妈` / `工作焦虑` / `我们的纪念日`。**意义全在桶名里**；桶类型名（轴）对检索无意义。"我们""用户自我"也只是这个集合里的桶，和 `妈妈` 平级，不单独成轴。

### 2.2 展示层（给用户用）【已定】
三个粗展示轴（从原来 6 个诗意名简化）：

- **我们**（关系本身的桶）
- **你**（用户自我/内在的桶）
- **你的世界**（其他人和外部生活的桶）

每个细桶在创建时挂一个粗轴标签。横跨的 filter/lens（不占轴）：`花苞`=open_thread 筛选视图、`常青`=pinned 标记、`四季`=时间线透镜。"Memory Garden" 作为整体概念保留。

### 2.3 桶的生命周期【已定，IO 自有设计（非借鉴 MemPalace）】
说明：MemPalace 的桶来自文件夹、天生唯一、不维护；IO 的桶由 LLM 即兴造名、必然漂移重复，所以**必须主动维护**。

- **写时规范化（resolve-before-create）**：每次落卡，proposer 先读现有桶列表（即召回用的那份紧凑索引，读写共用），**能复用就复用、实在没有才新建**。把"造桶"从生成问题变成选择问题，从源头压住漂移。
- enclave 在 commit 时对"新桶名"做廉价近重复检查，太像已有桶就驳回、建议挂到已有桶。
- 桶是有 `active / dormant / merged` 状态的轻对象；**做梦顺手维护索引**——合并近义桶、退休所有卡已解决/衰减的桶，但**永不删**。
- 索引自稳定：用得越多、可复用桶越多、新漂移越少。

## 3. 写入路径

### 3.1 落卡触发时机【已定】
对用户感觉像"自然就记住"，机制上在巩固时落卡，用户明说是强制覆盖：

- **会话内**：靠上下文/草稿即时记得，**不落卡**。"刚说你就忘"在会话内永不发生。
- **落卡发生在轻巩固**（自然停顿 / 会话收尾 / 每 N 轮触发）：带全段后见之明判断 + 写时去重。为什么不在聊天中途随时落——后见之明判断更准、出生即去重、批处理便宜、且接回"草稿→发布"模型。
- **深做梦**在轻巩固之上做更重的活（抽象、索引维护）。
- **用户明说"记住这个"** = 跳过质量门槛、立即落卡、高 confidence、可直接钉常青。
- 路径差别只在执行者：route A 的 agent 自己草稿 + 自己巩固；route B 由平台 capture 进程回看最近 chat history 巩固。
- 工程点：route A 会话内草稿需持久一会儿，**会话收尾必须触发一次轻巩固**，别等深做梦，否则极端情况会丢。

### 3.2 提炼 extraction【已定（prompt 待写）】
产物：`verbatim` + 一行 `summary`/label + `bucket_refs`（resolve-before-create）+ schema 字段。
质量门槛：Garden 标准——"如果要把这个人的故事讲给共同朋友，我会讲这条吗"。

### 3.3 落卡 integrate（commit 契约，路径无关）【已定】
- `commit(op, {label, bucket_refs, ...})`，op ∈ `insert` / `supersede(target)` / `merge(targets)`。
- 两条路调**同一个** commit 工具、同一套语义。
- enclave：校验 + 确定性状态迁移（supersede 改 status、连 superseded_by、设有效期窗口）+ 重算 decay + 近重复桶检查 + **永不硬删**。**不跑 LLM。**

### 3.4 矛盾消解【已定】
- 默认：更新 + 更高 confidence 当 active，旧的转 superseded；**用户亲口 > agent 推断**。
- agent 解不了的硬冲突：两张都留 active + 交叉标 `contradicted_by` + **主动浮现去问用户**（"我记得你之前说 X，现在是 Y 了吗"）——把矛盾变成一次关系性对话。

## 4. 冷启动 onboarding（两条路）

- **route A / VPS**：无蒸馏环节。agent 自带历史，bootstrap 让它从自己的记忆自蒸馏出身份 + 种子卡。
- **route B / API 导入**：用户上传聊天记录 / persona / Memory / AI 角色设定 → 蒸馏出 ① 语气规格（§5）② 一批种子卡，走 commit 批量 insert。
- **大文件处理**：按**会话边界**分块（不是按字数）；两遍——第一遍每块抽候选瞬间 + 人设信号，第二遍跨块去重 / 消矛盾 / 规范化桶 / 合成 persona；**覆盖校验**：每块强制至少一条结构化输出或显式标"无要点"，便于查出掉的尾部。
- 提炼优先级：**冲突/吵架记录 > 日常 > 甜蜜**（冲突最暴露真实人设，借 ex-skill）。

## 5. 语气规格 / Agent Persona（后端内容先落；UI 延后）

定位：**常驻、每轮操控生成**（区别于按需检索的卡）；五维雷达是它的**派生展示**，不是真相源。诊断：现有五维卡是"显示形态"不是"操控形态"，缺语气、不起作用——根因是存储形态被显示形态绑架。

路径差异：**完整六层主要在 API/导入路蒸馏**；VPS 路退成薄薄一层（只存"你想要的关系 + 在场偏好"，角色本体来自 agent 自己）。

六层【骨架已定，各层字段待填】：

- **0 底色 / 核心契约**——一句话的魂，最高优先级。
- **1 声音 / 语气**【承重】——句长节奏、亲密/正式语域、怎么称呼用户、怎么自称、口头禅、标点 emoji 习惯、各状态下怎么说。**全用例句，不用形容词。**
- **2 怎么爱**——表达在乎/想念/担心/逗/安慰/庆祝的具体手势。
- **3 相处与边界**——多主动、难过时怎么接、分歧时退还是顶、亲密尺度；**含健康边界**（不助长伤害、不有害占有），角色化写、不说教。
- **4 你想要的关系**【IO 独有】——用户共同定义想要的关系，反过来调上面所有层。
- **5 在乎与雷点**——用户对什么敏感、什么让 ta 觉得被爱/被疏远。
- **6 在场方式**——它怎么出现的风格（**只定风格、不定节奏**）；**最少蒸馏、最多向前学**（冷用户从"问用户想怎么被找"种子起步）；给 §6.3 surface 的语气染色。

## 6. 读取

### 6.1 召回 recall（agentic、只读库、路径无关）【已定】
- `index()`：enclave 解密返回紧凑索引（桶名 + 一行 label + 状态）。
- agent 限范围（定不出范围就跨范围读 label、用推理关联）→ `fetch([ids])` → enclave 解密返回 verbatim → agent 精读。
- 形状同 MemPalace："便宜粗筛 → 昂贵精读"；但第一段用 summary/结构而非向量，第二段（agent 读 fetch 回的 verbatim）是真正贡献准确率的部分，必须做扎实。
- 卡量涨到几百张以上才加廉价预筛（recency + jieba）把索引切片限界。
- **向量 = 写明的 scale-out 后备杠杆**：需 enclave 内嵌 embedding 模型（不可走外部 API）+ 一次 compose_hash 链上治理事件；用 eval 量到模糊召回确实在掉之前**不上**。

### 6.2 上下文注入 assembly【已定（数值起步、测试再调）】
每轮 memory 相关预算起步值：语气规格 **~700 token**、索引切片 **~400**、取回卡 verbatim **~1,500**，合计 **~2,600 / 轮**。索引切片用完即弃，**只有取回卡进最终回复上下文**；open_thread 排前；标注为记忆。测试时按实测 token 收放。

### 6.3 主动浮现 surface()【输出契约已定】
- 输出：排序候选 = {待跟进的 open_thread + 高 salience 久未露的卡，各带"为什么值得提" + 一个建议语气（来自在场风格）}。
- 这是**记忆的主动浮现**，回答"该说什么、用什么口吻"；**不是** IO Proactive System 的时机决策。
- memory ↔ Proactive 接口：surface() 的输出形状现在定；"要不要戳、什么时候戳"是 Proactive System 的活，【延后】到讨论它时再定。

## 7. 维护

### 7.1 衰减 decay
- 机制【已定】：importance + last_active 驱动，affect 加权（Ombre 式）；`pinned`/`decay_exempt`/未解决的 open_thread **豁免**（防 Ombre 永久桶被一视同仁衰减、掉到阈值下的 bug）。
- 参数【待 eval 定参】：具体公式与系数不在 eval 前拍死。

### 7.2 做梦 consolidation【机制已定，参数待 eval】
- 调度：轻巩固勤跑（停顿/收尾/每 N 轮）+ 深做梦稀跑。在 enclave 内、作为一个 proposer 走 commit。
- 操作（优先级）：① 去重 merge ② 矛盾检测 → 提问 ③ 抽象（一簇 episodic → 一张 semantic 新卡，episodic 降权不删）④ 重打分 ⑤ 排队 open_thread 喂浮现 ⑥ **维护索引**（合并近义桶、退休 dormant 桶）。
- **可见性红线**：加法 + 闸门，**永不删、永不静默改写用户可见的卡**；历史靠 supersede-永不删保留；用户端只看到"加法 + 温和标注"，不看到剧烈变化。
- 早期保守：只做 ①②⑤⑥；抽象（③）加置信门槛或以"我可以这样理解你吗"露出，等 eval 再放松。

### 7.3 删除 / 留存0【已定】
- 用户主动删 = **真硬删**（被遗忘权）；supersede / 做梦 = 软（保留）。
- "留存0" = TEE 平台读不到的保证，**不等于"什么都不记"**；文案别混。
- archived/superseded 卡：默认排除出召回/索引，但保留供历史/回滚；不进入活跃集，无无界增长问题。

---

## 8. 用户可控 / 透明【已定】
- 终端用户：看 Garden；删（真删）/ 改（走 supersede 保留链）/ 钉（常青）；**不露出回滚**。
- 内测用户：对落卡内容的完整增删改。
- 透明：权威库 = 用户可见面，草稿永不展示。

---

## 9. eval（横切）【机制已定，rubric 待扩】
- 顺序铁律：**eval 打地基，没 eval 前别动记忆规则。**
- 两类判官：机器判（漏记/记错/类型/R@5 + 安全死线：日志不得现明文 key）+ AI 品味判（**先列理由、最后才打分**，两两对比）。
- golden set / rubric 扩展覆盖：① scoping 准确度（选对桶没）② label 质量（agent 能否据此判断）③ 浮现相关性 ④ **语气规格遵循度**（输出像不像 spec 的声音——尤其这项，用品味判官两两对比）。
- 工作法：拆"草稿→找茬→改"；AI 找茬放后台。

---

## 10. 隐私 / enclave 边界【已定】
- 单信封、全加密（verbatim / label / 桶名 / 元数据），enclave per-request 解密，外部无明文。
- 解密便宜（ChaCha20 GB/s），可全解；不需要为"省解密"做轻信封。
- 向量若上：需 enclave 内嵌模型（外部 API 会泄明文，禁用）+ compose_hash 链上治理 + 重新 attest。

## 附：参考来源与取舍（为什么这里抄这个、那里抄那个）
- **imprint-memory（MIT）**：jieba 中文分词（解"东方Project"分词问题）、dedup/decay 原语（属整合层）。混合检索 RRF 是其强项但 IO 走 agentic 路、暂不用。
- **Ombre-Brain（MIT）**：affect 加权 decay 公式、主动浮现（breath）思路、lifecycle schema 灵感。
- **MemPalace（MIT）**：两段式"粗筛→精读"的形状、有效期窗口的演化链模型。其桶是文件夹派生的静态过滤器、不维护——IO 桶涌现故需自建维护（§2.3）。
- **memU**：贡献"充分性检查"一个检索点；其 agent 涌现式 folder 作为**存储**是反面教材（会破坏统一契约），但作为**索引**涌现 OK。
- **ex-skill（MIT）**：onboarding 蒸馏（聊天记录→分层 persona）、"冲突记录优先"启发式、merge-不覆盖 + correction-叠加思路。其六层为"复刻真实前任"设计，IO 的语气规格按 companion 重设计（§5），去掉"消失预兆"类层、倒转为"在场方式"。
